# Two floated panels land clear of one another, and dragging one's tab twice moves the same window.
#
# **Reported by the artist**: with Pages and History floating, dragging the Pages tab worked, and
# dragging the same tab again picked up History. The cause was the placement. A new window was
# offset from the last by one header -- twenty-eight units on a window of three hundred and twenty
# by three hundred and thirty-eight -- so two of them overlapped by better than nine tenths and
# read as one. Dragging the top one's tab even a little dropped it *inside* the one beneath, which
# is the merge gesture: the two became one window, and the tab under the pointer then belonged to
# the other panel.
#
# There was a test for this and it passed throughout. It asked whether the second window was offset
# from the first by at least one header. It was -- by exactly one.

tab Pages
holdat 1900 91
press Float
expect layout *Menu / *Tools / *Canvas / *Layers,History,Page / *Brush,Transform,Select,Text / *Colour | Pages
expect windows 60,60 320x338

tab History
holdat 1900 91
press Float
expect layout *Menu / *Tools / *Canvas / *Layers,Page / *Brush,Transform,Select,Text / *Colour | Pages / History
# Side by side with a clear gap, not stacked: the second window's left edge is past the first
# window's right edge, which is the whole of the fix.
expect windows 60,60 320x338 / 388,60 320x338
shot windows-apart

# **The same tab twice.** Each drag moves the window it belongs to, and only that one. The second
# is the one that used to pick up the neighbour.
drag 140 91 240 191
expect windows 160,120 320x338 / 388,60 320x338
shot windows-dragged-once
drag 240 151 340 251
expect windows 260,180 320x338 / 388,60 320x338
shot windows-dragged-twice
