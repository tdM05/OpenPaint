# Every key the application answers, driven at the keyboard rather than through a panel. The two
# routes in must not become two behaviours, which is the whole reason `history_step` is shared.

# Tools.
expect tool Brush
key e
expect tool Eraser
expect status Eraser
key b
expect tool Brush
expect status Brush

# Brush size steps by a ratio, so two presses one way and two back land where they started.
expect brush.size 8.000
key ]
key ]
about brush.size 10.58 0.2
key [
key [
about brush.size 8 0.1

# The view. Bare 0 is fit and bare 1 is actual size -- deliberately not Ctrl+0, whatever the
# doc comment above `handle_navigation` says.
key 1
about zoom 1 0.001
key 0
about zoom 0.59 0.05
shot kb-fit

# Rotation, about the cursor, fifteen degrees a press. Four one way is a sixth of a turn.
move 900 700
expect rotation 0.0000
key shift+]
about rotation 0.2618 0.01
key shift+[
about rotation 0 0.001

# Undo and redo, both spellings of redo.
drag 700 400 1100 800
expect undo 1
key ctrl+z
expect undo 0
expect redo 1
key ctrl+shift+z
expect undo 1
key ctrl+z
key ctrl+y
expect undo 1
expect redo 0

# Selection from the keyboard. Select all, then deselect.
key ctrl+a
expect selection true
key ctrl+d
expect selection false

# Invert has to be tried on part of the page, not all of it: the opposite of everything is
# nothing, and a selection of nothing is correctly not a selection at all. So take a rectangle
# first, and then the inverse of that is still a selection.
press Rect
drag 600 350 1000 700
expect selection true
key ctrl+shift+i
expect selection true
key ctrl+d
expect selection false
press Brush

# And the degenerate case said out loud, because it is a decision rather than an accident:
# inverting the whole page leaves nothing selected.
key ctrl+a
expect selection true
key ctrl+shift+i
expect selection false

# Fill paints the selection with the brush colour, and that is an edit, so history grows.
key ctrl+a
expect selection true
# The status is written by the same function that would write it after filling zero pixels, so the
# proof is the page: a box that was clear before is covered afterwards, and clear again on undo.
ink 1200 900 1350 1050 0
key ctrl+f
expect undo 2
ink 1200 900 1350 1050 2000
shot kb-filled
key ctrl+z
expect undo 1
ink 1200 900 1350 1050 0

# Delete clears the selected pixels -- only with a selection up, which there is.
key ctrl+a
ink 600 400 800 600 20
key delete
expect undo 2
ink 600 400 800 600 0
key ctrl+z
expect undo 1
ink 600 400 800 600 20
key ctrl+d

# F4 cycles the theme. It is a setting with no other witness -- it changes every colour on screen
# and nothing a document could show -- so until the application would name it, F4 was proved not to
# crash and nothing else.
#
# F2 used to swap the whole UI for the old side panel and back. There is no old side panel any
# more, so there is nothing to swap to and no `workspace-mode` to assert; the key is unbound.
expect look Studio Line
key f4
expect look Paper Line
shot kb-theme
key f4
expect look Studio Line
shot kb-workspace

# Ctrl+E asks where the artwork is going rather than writing a file on the spot. What is asserted
# here is the shortcut: the question comes up, and Escape puts it away having changed nothing.
# `export.txt` drives the dialog itself and reads the files off the disk afterwards.
expect dirty true
key ctrl+e
wait 800
expect exporting true
shot kb-exporting
press Not now
expect exporting false
expect dirty true
shot kb-exported

# Backspace clears the selected pixels, exactly as Delete does -- two keys, one behaviour, and only
# one of them had ever been pressed.
key ctrl+a
expect selection true
ink 600 400 800 600 20
key backspace
ink 600 400 800 600 0
key ctrl+z
ink 600 400 800 600 20
key ctrl+d
