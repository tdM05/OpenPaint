# The menu bar: every menu, and every item in them that is safe to drive.
#
# The drop-downs are the workspace's popup rather than egui menus, so an item is a control in
# the atlas like any other -- which means a `press` that resolves at all is already proof that
# the menu opened, because a step naming something not on screen stops the run.
#
# Every press below says `Menu:` first. A drop-down is drawn by the panel that owns it, so the
# menu bar and its lists are all filed under Menu -- and half these words belong to a panel as
# well. The Layer menu's Add and the Layers panel's Add are one name; so are the Select menu's
# Clear and the Select panel's Clear, and Undo and Redo and Fill selection. The atlas refuses a
# name that fits two controls, deliberately, and saying which panel is meant is the answer.
#
# Three of these items hand the machine a native file dialog, and this harness cannot answer
# one: it blocks on its own thread and no control of ours is on screen while it is up. Those
# are driven only as far as "the request was made" -- `dialog true` -- and then dismissed with
# Escape. Nothing in the application reads Escape while a file dialog is up (the dialog owns
# the foreground window and `poll_file_dialog` only ever collects the answer), so the key goes
# to the dialog and cancels it.
expect layers 1
expect layer-names Layer 1
expect undo 0
expect dirty false
expect confirm false
expect dialog false

# File > New, from a clean document: nothing to lose, so no question is asked, and what comes
# back is one empty layer with an empty history.
press Menu:File
press Menu:New
expect status New document
expect confirm false
expect layers 1
expect layer-names Layer 1
expect undo 0
expect dirty false
expect file -
shot menu-new

# The bar button lights while its list is down, and pressing it again puts the list away.
# Closing a menu is not a command: nothing about the document may have moved.
press Menu:File
press Menu:File
expect layers 1
expect dirty false
expect status New document

# File > Open. Driven while the document is still clean, so the unsaved-changes question does
# not stand between the press and the dialog. Cancelling must leave the document untouched.
press Menu:File
press Menu:Open
wait 2500
expect dialog true
key escape
wait 900
expect dialog false
expect file -
expect dirty false
expect layers 1
shot menu-open

# File > Save on a document with no file of its own falls through to Save As, so it is a
# dialog too -- and a cancelled save must not invent a path.
press Menu:File
press Menu:Save
wait 2500
expect dialog true
key escape
wait 900
expect dialog false
expect file -
expect dirty false

# File > Save As always shows the picker, whether or not the document has a file.
press Menu:File
press Menu:Save As
wait 2500

key escape
wait 900

expect dirty false
shot menu-saveas

# View > Actual size is exactly one document pixel per screen pixel, whatever the window.
press Menu:View
press Menu:Actual size
expect zoom 1.0000
shot menu-actual

# View > Fit puts the whole 2048-square page inside the canvas, so the scale it lands on is
# whatever this window makes it -- a number no scene can name. The band is wide on purpose:
# its one job is to say that Fit is a real scale and that it is not 1:1.
press Menu:View
press Menu:Fit
about zoom 0.5 0.49
shot menu-fit

# Something to undo. The page is fitted, so a drag across the middle of the window is a stroke
# on it -- and the undo stack is the evidence that dabs actually landed.
drag 500 300 900 700
expect undo 1
expect dirty true

# Edit > Undo and Edit > Redo, which are the same two steps the History panel offers.
press Menu:Edit
press Menu:Undo
expect undo 0
expect redo 1
shot menu-undone
press Menu:Edit
press Menu:Redo
expect undo 1

shot menu-redone

# Select > All, and the mask it leaves behind.
press Menu:Select
press Menu:All
expect selection true
expect status Selected all
shot menu-selected

# Select > Invert. Inverting everything leaves nothing, and an empty result is recorded as no
# selection at all -- after which the menu no longer offers Invert, because there is nothing to
# invert and a menu here never offers what it would refuse. The other half of the pair, that
# inverting nothing selects everything, is still reachable from the keyboard, and that asymmetry
# is deliberate: a key is a power path, a menu is what tells you what is available.
press Menu:Select
press Menu:Invert
expect selection false
expect status Inverted the selection
key ctrl+shift+i
expect selection true
expect status Inverted the selection

# Select > Deselect drops the mask.
press Menu:Select
press Menu:Deselect
expect selection false
expect status Deselected

# Edit > Fill selection needs something selected, so the mask goes back first. The status only
# reads "Filled the selection" when the fill was recorded, which is what makes it the check:
# an unrecordable fill says so instead.
press Menu:Select
press Menu:All
expect selection true
press Menu:Edit
press Menu:Fill selection
expect status Filled the selection
expect dirty true
shot menu-filled

# Edit > Transform selection lifts what is selected and holds it in the air. It is in a menu
# because beginning a transform is a command; the sliders that steer one live in Tool options
# while it is up, which is `transform.txt`'s subject. Cancel here, so the rest of this scene meets
# the document it expects.
press Menu:Edit
press Menu:Transform selection
expect dragging true
shot menu-transforming
key escape
expect dragging false

# Select > Clear is the other half of fill: the pixels inside the mask come off the active
# layer, and that is recorded the same way.
press Menu:Select
press Menu:Clear
expect status Cleared the selection
expect dirty true
shot menu-cleared
press Menu:Select
press Menu:Deselect
expect selection false

# The Layer menu. Four of its items are word for word the Layers panel's four buttons; the fifth
# makes a text layer, and it is here rather than in the panel that edits captions because it makes
# a layer rather than describing one -- and because the one place somebody who has never made a
# text layer will not look is inside the panel that has nothing to show until they have.
press Menu:Layer
press Menu:Add
expect layers 2
expect active.name Layer 2
expect status Added layer 2
shot menu-layer-added

# Add text layer, offered whatever is active, and the only way to make one.
press Menu:Layer
press Menu:Add text layer
expect layers 3
expect active.kind text
expect active.name Text
shot menu-text-layer
key ctrl+z
expect layers 2
expect active.kind raster

press Menu:Layer
press Menu:Duplicate
expect layers 3
expect layer-names Layer 1, Layer 2, Layer 2 copy
expect active.name Layer 2 copy

press Menu:Layer
press Menu:Merge down
expect layers 2
expect layer-names Layer 1, Layer 2
expect active.name Layer 2

# Delete is the fourth item, and it is only built at all while there is more than one layer.
# Unlike Add and Duplicate it is undoable, and that is the half worth driving.
press Menu:Layer
press Menu:Delete
expect layers 1
expect layer-names Layer 1
key ctrl+z
expect layers 2
expect layer-names Layer 1, Layer 2
shot menu-layer-deleted

# File > Export puts the export dialog up rather than writing anything. Driving it to a file is
# `export.txt`'s job; what is asserted here is that the menu item asks the question and that
# putting the question away changes nothing about the document.
press Menu:File
press Menu:Export
expect exporting true
expect dialog false
shot menu-exporting
press Not now
expect exporting false
expect layers 2
expect dirty true
shot menu-exported

# File > New on a document with unsaved work, which is the one item here that could throw
# work away -- so it is last, and it is only ever cancelled. Escape answers the unsaved-changes
# question with Cancel, and Cancel is the answer that keeps everything.
expect dirty true
press Menu:File
press Menu:New
expect confirm true
shot menu-confirm
key escape
expect confirm false
expect layers 2
expect layer-names Layer 1, Layer 2
expect dirty true
shot menu-cancelled

# View > Settings, right at the end, because what it opens is the workspace's own popup and it
# stays up under a name of its own. Reaching "Words" inside it is the proof it opened, and
# choosing a look is a setting rather than an edit -- so the document must be exactly where the
# block above left it.
expect look Studio Line
press Menu:View
press Menu:Settings
press popup-workspace:Words
expect look Studio Words
expect layers 2
expect layer-names Layer 1, Layer 2
expect dirty true

# --- What the menus do NOT offer ---
#
# Every rule about hiding a command that would be refused was enforced by unit tests and by nothing
# that had ever looked at the running application. `absent` is the assertion for them. It passes
# trivially when the panel holding the item is not showing either, so each block opens its menu
# first and checks something that IS there alongside what is not.

# Nothing selected: Select offers only All, and Edit does not offer Fill.
key ctrl+d
expect selection false
press Menu:Select
press All
press Menu:Select
press Deselect
expect selection false
press Menu:Select
absent Menu:Deselect
absent Menu:Invert
absent Menu:Clear
press Menu:All
expect selection true
press Menu:Select
press Menu:Deselect
press Menu:Edit
absent Menu:Fill selection
absent Menu:Transform selection
press Menu:Undo
shot menu-absences
